# Introduction

Shin is a small, fast, cross-platform 3D engine that humans, scripts, and
AI agents all drive through the same API.

It is open source and written end-to-end in Rust. The crates.io package is
`shin-engine`; the library is `shin`, so code reads `use shin::...`. The
source lives at <https://github.com/nikolagigic/shin-engine>.

## The five rules

Shin is built on five rules, described in the repository README under
[Philosophy](https://github.com/nikolagigic/shin-engine#philosophy): the
world is an entity-component-system, singletons are resources, tools are
the API, data is plain files, and small and explicit beats clever. They
describe the code as it is, not a wish list, and every page of this guide
is an instance of one of them.

The rule that shapes this guide most is the third one: every capability
is a named, schema-described **tool** on a headless engine. The editor's
panels, the Console, the MCP server that agents talk to, scripts' tools,
and the test suite all call the same tools. Anything the editor can do, an
agent can do; anything an agent can do, a test can reproduce. The
[Tools reference](reference/tools.md) is generated from that registry.

## What works today

Shin is pre-alpha. Milestones 1 and 2 are complete, which means:

- A **wgpu** renderer (Metal, Vulkan, DX12, and WebGPU from one code
  path), a **winit** window, and a fixed-timestep game loop with
  variable-rate rendering.
- A **hecs** entity-component-system with plain-function systems and a
  typed resource map.
- **glTF** meshes, base-colour textures (PNG, JPEG, or glTF images),
  built-in cube and sphere meshes, and instanced drawing of one lit
  pipeline.
- **Headless golden-image tests**: scenes are rendered offscreen and
  compared pixel by pixel against committed PNGs.
- **Projects**: `shin new` writes a runnable game with a `shin.toml`
  manifest, a starter scene, and its own MCP server.
- An **egui editor** with a live viewport, scene tree, inspector, undo
  and redo, a tool console, and play, pause, and stop.
- **Scene files** in RON that you can read, diff, and edit by hand.
- **Rhai scripting** with hot reload: change gameplay without
  recompiling.
- **MCP**: every engine tool, plus a project's own tools, served to an
  agent such as Claude Code over stdio.

Deliberately missing for now: a scene hierarchy, an event system, a
parallel schedule, physics, and more than one lit pipeline.

## How this guide is organised

[Getting started](getting-started.md) takes you from a clean clone to a
running window and a running editor. [Projects](projects.md),
[The editor](editor.md), [Scenes](scenes.md), [Scripting](scripting.md),
and [Agents and MCP](agents-mcp.md) each cover one way of driving the
engine. The reference section has the generated
[Tools reference](reference/tools.md), an [Architecture](architecture.md)
tour for people reading the code, and [Contributing](contributing.md).

Every command and file in this guide is taken from the repository, and the
tools reference is regenerated by a test, so what you read here is what
the code does.
